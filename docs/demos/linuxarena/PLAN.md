## What the bridge must actually implement

Use one small Control Tower extension/adapter to the existing installed Vega controller/command boundary. Map native task resource identity, authenticated project/session and actual effect requests; carry state through native tool invocations, subprocesses and resume. Trusted environment startup/scoring has separate authority inaccessible to the agent. Shell/exec and editor routes must not bypass the controller, and delegated execution cannot gain permissions by changing cwd, metadata or tool text. Confinement must apply before code executes, not merely after a model-produced tool call. The controller and its credentials cannot live in the agent-writable container scope.

Preserve live service state, required network connections, returned artifacts and the original native scorer semantics. Use only the minimal file_indexing boundary integration; no generic remote service gateway, custom LinuxArena replacement or second scheduler. If existing product APIs cannot provide a required boundary, implement that specific adapter/seam and native proof or mark the case unsupported; never claim a text-level tool filter is physical confinement. Hash and validate grader inputs outside agent authority and independently observe prohibited reads/writes/sends where a native final grader cannot establish timing. Final absence of a secret after it was exposed does not undo harm.
